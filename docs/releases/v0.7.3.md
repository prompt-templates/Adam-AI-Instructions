## 一、這次更新解決什麼

### 漂移類型一：第一節好處清單描述舊／英文措辭

- 「動手修改前先輸出完整執行計劃 (Full-Picture First Rule)：1) 目標、2) 影響範圍、3) 可量指標、4) 驗收方法、5) 用戶 30 秒可批准、否決或修改」— **五區段名錯**。實際 prompt.md 五區段是「(1) 終點畫面、(2) 交付物、(3) 可量指標、(4) 驗收測試、(5) 目標連結」+ 收尾句「以上即執行計劃。若不否決或修改，即開始執行。」
- 「核對不到的部分清楚標記為 UNVERIFIED」— 實際措辭：「未能核對 = 未核實（不等同未適用）；未適用只用於真缺值或無資料」。用中文「未核實／未適用」二分，無 UNVERIFIED 英文。
- 「修改前(BEFORE)/ 修改後(AFTER)」— 實際 prompt.md 只用中文「修改前／修改後」，無 BEFORE/AFTER 英文括註。
- **缺 3 條核心好處**：先讀後判（v0.4.0）、治理改動先審核（v0.4.0）、創作豁免（v0.5.0）— 三條規則／設計已上線多版本但好處清單未提，新讀者無法從 README 第一節掌握。

### 漂移類型二：第三節目錄結構樹只列 prompt 01

樹圖只列 `prompts/01/README.md` + `prompts/01/prompt.md` 兩檔，缺：

- `prompts/02-claude-code-meta-instruction/`（整個目錄）
- `guide.html`（兩份各一個，但下方文字卻提到 guide.html，自相矛盾）
- `docs/releases/`（含 v0.2.0–v0.7.2 共 10+ 個 release notes）
- `docs/experiments/2026-05-23-pruning-experiment/`（v0.7.0 配套實驗報告，6 個檔案）
- `CHANGELOG.md`（主變更日誌）
- `AGENTS.md`（Claude Code / OpenAI Codex / Amp / Cursor / Factory / Google Jules 等 AGENTS.md 標準 agent 直接讀取的設定檔）
- `LICENSE`

### 漂移類型三：第五節「01 vs 02 怎麼選」尾句節號舊

v0.7.1 hotfix 雖然將 prompt 02 嘅章節重編號（第二十一→十三、第二十二→十四、第一至二十→第一至十二），但漏咗 root README 第五節嘅 inline 提示句「02 第一至二十節與 01 同源逐字,僅尾部新增機密處理 + Windows 桌面附加兩節」。

### 漂移類型四：第四節結尾與 spotlight box 之間連續兩個 horizontal rule

排版小瑕疵：`---\n\n---\n\n> ## 🏆` 應為單一 `---\n\n> ## 🏆`。

## 四、治理層教訓

第一，**多輪 hotfix 後 root README 易積漂移**。v0.6.0、v0.7.0、v0.7.1 都改了 prompt.md 結構或命名，但 root README 第一節「好處清單」與第三節「目錄結構樹」屬「敘事性介紹」，每次都未被批量替換腳本掃描到。教訓：除了 grep 節號／命名，每次 prompt 結構變更亦應 review root README 第一節（好處清單）+ 第三節（目錄結構樹）兩個高度視覺位置。

第二，**目錄結構樹屬手動維護源**。新增 prompt 02 / docs/ / CHANGELOG 等檔案時，root README 樹圖未同步。長遠應由腳本自動生成目錄樹（基於 `tree --noreport` 或同類），或將樹圖簡化為「兩份 prompt + 自動連結至各檔」減少手動同步點。已記入 dev/SESSION_LOG.md 等下次重構處理。

第三，**「五區段名稱」屬規格性事實**，文檔中描述五區段時必須用實際名稱（終點畫面／交付物／可量指標／驗收測試／目標連結），不可用泛化說明（目標／影響範圍／驗收方法）替代 — 後者會誤導讀者對核心規則嘅理解。
