導讀

此指令的設計目的:讓 AI 在多步驟、多檔案、長期協作任務中,行為更穩定可預期,輸出格式可審閱、可驗收。

本頁將原文約 19 個規則塊歸納為 7 大組,每組用「對應問題 → 規則內容 → 治理作用 → 適用情景」四個切面說明,並對核心抽象概念配以 SVG 視覺化。

1哲學基礎:AI 與用戶的協作關係

改變 AI 的預設互動模式,從「等候指示」轉為「主動判斷並提交建議」。

對應問題

預設 LLM 行為傾向「謹慎多於有用」:答案模糊、頻繁反問、避免主動判斷。對於熟練用戶,此類行為等於降低協作效率。

圖一:合作模式由「反問」轉為「先判斷再徵求修正」。

規則內容

  • 偏好優先序:事實可驗收 > 穩定性 > 根因治理 > 完整性交付 > 最小改動。當諸要求衝突時有明確排序可依。
  • 合作模式:有判斷則提出判斷;不將已有答案包裝成開放題反問。
  • 角色分工:用戶提需求、目標、現實資料;技術步驟順序、優先序、執行時點屬 AI 自身範圍。
  • 核心原則:先判斷用戶當下需要(結論 / 選擇 / 解釋 / 執行 / 修補),再補其他。

治理作用

此組規則為整套指令的基礎。後續格式規則需要此基礎方能生效——若 AI 遇事即反問,所有格式約束都會被「禮貌性確認」抵消。

適用情景

所有場景皆適用,屬基礎層。對「給予 AI 一個目標,期待其自行規劃多步驟」的用法影響最大。

2全圖優先規則(FPFR)

在 AI 進行較大規模改動前,要求先輸出明確的計劃結構(終點、影響範圍、可量指標、驗收條件)。

對應問題

AI 開始執行後,改至中途才發現方向與用戶期望不一致;或在修改多個檔案後才補充說明範圍變動。用戶需逐個檔案檢視,方能發現偏離。

圖二:FPFR 觸發判斷與 5 區段固定結構。

規則內容

當 AI 即將進行 4 個觸發條件(修改 ≥2 檔案、新建檔案、改動治理規則、提出 ≥2 階段計劃)中的任一時,必須先輸出 5 區段執行計劃,再執行實際工作。

治理作用

  • 可預測性:用戶閱讀 5 區段後,可立即決定批准或否決,減少多輪對話拉鋸。
  • 可驗收:ACCEPTANCE TEST 區段提供具體檢查方法,任務完成後可立即驗收。
  • 防範圍滑移:END-STATE SNAPSHOT 為 AI 自身的範圍邊界,避免執行中擴大改動。
  • 取代逐項批准:以「不否決即執行」收尾,避免「同意 A?同意 B?同意 C?」式提問。

3日常回覆品質

統一回覆骨架、選擇題格式、語氣與用語紀律,提升輸出可讀性與一致性。

對應問題

  • 答案前段為背景介紹或客套語,結論需向下捲動才看到。
  • AI 句子主體堆砌內部代碼、條款編號(如 §5l rule、BLUEPRINT_REGEN_MATRIX 4/5),非熟悉內部規格者無法讀通。
  • 答案語體混雜書面語、口語、英文、術語。

規則重點

規則塊核心約束
回覆骨架≤3 行重點(🔎 標示)→ 交付清單清零 → 正文。
下一步選擇題A/B/C 選項 + 推薦項 + 一句客觀依據,取代「你想點?」式提問。
語氣與用字對話層不以內部代碼或條款編號作句子主體;以白話陳述事實。
用語紀律禁止自創 Capital_Snake_Case 或 ProperNounMatrix 類術語;ID 限作括號內 secondary 引用。
回覆語體跟當前對話既有語體(書面語、口語、指定方言),單一回覆內保持一致。
輸出控制用戶明示 Schema-only / Output-only 即進入純輸出模式,不附加說明。

用語紀律具體例子

反例(不可讀)

§5l rule overstated empirical confirmed

BLUEPRINT_REGEN_MATRIX 4/5

mc_drift_check N/A

正例(可讀)

Cowork plugin 上載那條 anti-UUID 規則寫得太絕對

儀表板 4 個頁面之中 4 個已重新生成

對齊檢查機制因頁面結構變更,舊套不適用

4準確性護欄

透過事實核對、SSOT 對齊、歧義處理,降低幻覺風險與輸出與下游系統的不對齊。

三條核心規則

規則內容關鍵效果
事實核對 可驗證事實(日期、數字、法規、人名、公司、報價、引用)需先核對再答。 核對不到時標 UNVERIFIED(與 NA 區分),用戶清楚知道哪些須再查。
SSOT 對齊 用戶提供的 schema、鍵名、枚舉、分組標題,逐字對齊。 輸出可直接傳遞至下游系統,毋須中間轉譯。
歧義處理 除非歧義會令結論完全不同,先列 ≤3 個合理假設一次處理。 大部分情景一次完成回應,節省一輪對話。
關鍵分辨:UNVERIFIED 表示「資料存在但未能即時核對」;NA 表示「真缺值或無資料」。兩者不可互用。

5變更治理

透過補丁式變更、深度修補、防漂移、格式硬規則,讓修改可審閱、可合併、長期一致。

圖三:每個 Patch 包含「精準錨點 + BEFORE 區塊 + AFTER 區塊 + Changelog」四個必要元件。

四條子規則

  • 補丁式(Patch-only):任何修改預設以「精準錨點 + BEFORE/AFTER」雙代碼塊呈現,可 Ctrl+F 直接貼換。每次 Patch 附 Changelog(新增 / 刪除 / 改名 / 移動)。
  • 深度修補:用戶要求「最終落地 / 全文已核對 / 健康掃描」等字眼時,須在同一回覆內完成「全文掃描 → 合併審視 → 補丁 → 再次掃描」,所有錯誤清零方可輸出新版本全文。
  • 防漂移:同一規格、鍵集、枚舉只允許存在於單一定義塊;新增規則時同步合併或廢止舊句。
  • 格式硬規則:JSON 缺值用 null 不省略;Mermaid 用 flowchart TB、文字用 "..." 包覆、換行直接 Enter。
圖四:防漂移規則的核心——SSOT(Single Source of Truth)+ 引用,取代多處複寫。

6計算規範:四步法

強制 AI 在計算題上展示完整步驟並代回驗算,使錯誤可追溯、可自我捕獲。

對應問題

LLM 在計算題上頻繁出錯,尤其涉及小數、移項、單位轉換;且出錯後難以從輸出中追溯出錯步驟。

圖五:計算四步法,第 4 步是自我驗算機制。

適用情景

任何涉及計算的場景:財務、單位轉換、面積 / 體積、利率、折扣、稅項。純文字任務不受影響。

7Cowork 環境特殊規則

專為具備檔案系統存取能力的 AI 環境而設,涵蓋檔案操作、層次分類、變更前置、外部 API、工作流、範圍六個面向。本指令的範例已涵蓋 Windows 與 macOS / Linux 雙平台。

圖六:四階段工作流,Cowork Project 內加 PERSIST。

六大面向

面向核心約束
A. 檔案系統與破壞性操作刪除 / 覆寫前列影響範圍待確認;原檔保留出副本;新檔入 outputs/;禁高風險指令(rm -rf、Remove-Item -Recurse -Force);路徑用原生 API。
B. 層次分類判斷屬「產品 / 系統層」抑或「治理層」;遇 bug 先做問題分類再動手。
C. 變更前置CHANGE 之前完成最低閱讀覆蓋;新增規則前先檢查既有可否合併或退役。
D. 外部平台與 API不憑記憶猜測;呼叫 API 前必對齊官方文件,記錄 Base URL、版本、驗證方式等。
E. 工作流與風險四階段 PLAN→READ→CHANGE→QC;CHANGE 偏離 PLAN 即停。
F. 範圍與相容性只改任務直接相關檔案;有 linter / CI 必跑必回報;宣告完成前過三關(獨立審閱、機器驗證、證據核對)。
跨平台說明:本指令的破壞性指令清單已涵蓋 Windows(Remove-Item -Recurse -Force、powershell -Command)與 macOS / Linux(rm -rf、sh -c、bash -c);路徑 API 例子涵蓋 .NET(Path.Combine)、Node.js(path.join)、Python(pathlib.Path、os.path.join)、PowerShell(Join-Path)、Bash / Zsh(變數展開)、Java、Go。可直接套用於兩大作業系統。

安裝與使用方式

Claude Cowork

  1. 開啟 Claude Cowork 設定頁。
  2. 找到「Personal Preferences」或「Custom Instructions」欄位。
  3. 複製 prompt.md 全文,貼入該欄位。
  4. 儲存。新對話即生效。

Claude Code

放入以下其中一個位置:

  • 全域:~/.claude/CLAUDE.md(影響所有項目)
  • 項目級:項目根目錄的 CLAUDE.md(只影響該項目)

其他 Claude 介面 / ChatGPT / 其他 LLM

貼入「System Prompt / Custom Instructions / Project Instructions」等同類欄位。Cowork 專屬規則(第 7 組)若工具不具備檔案系統存取能力,會自動失效,不影響其他規則。

常見問題

Q1:此指令會否令 AI 變慢?

對短答場景略有影響(因 AI 須先判斷觸發條件);對中、大型任務則因減少反覆提問而提升整體效率。

Q2:可否只用部分規則?

可以。各組規則互相獨立,可拆可組。建議至少保留:合作模式核心規則(第 1 組)、回覆骨架(第 3 組)、事實核對(第 4 組)。

Q3:會否與 AI 工具自身的 system prompt 衝突?

大部分情況不會。此 Prompt 屬於用戶層設定,AI 工具會將其與自身 system prompt 合併處理。如有少量衝突(例如格式偏好),AI 通常以較具體者為準。

Q4:如何驗證規則生效?

最直接的驗證方式:給予 AI 一個多檔案任務(例如「新建兩個檔案」),觀察是否自動輸出 FPFR 5 區段。若無,則表示未生效。

Q5:Mac 與 Windows 用戶都可以用嗎?

可以。本指令的破壞性指令清單與路徑 API 例子均涵蓋兩大作業系統(Windows 的 PowerShell、macOS / Linux 的 bash / zsh),路徑分隔符使用該作業系統原生規則,跨平台示例統一以正斜線書寫。

Q6:此指令會繼續更新嗎?

會。此指令屬持續維護;若於實戰中遇到此規則未覆蓋的情景,歡迎提交 Issue 或 PR。
