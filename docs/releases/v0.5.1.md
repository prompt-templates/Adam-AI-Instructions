# v0.5.1 — Hotfix：主標題對齊跨工具通用聲明

**發布日期**：2026-05-16
**主旨**：修正 v0.5.0 release 嘅一個 inconsistency bug。v0.5.0 已聲明跨工具通用（Codex / Amp / Cursor / Factory / Google Jules）並 retitle 第二十節，但主標題「# Claude Cowork 全域指令」仍 hardcode "Cowork"，名實不一致。本 hotfix 修主標題 + 連帶幾處 Cowork hardcode + sync prompts/01 README 描述。

---

## 一、這次更新解決什麼

### 痛點：主標題同章節跨工具通用聲明矛盾

**v0.5.0 已做嘅 cross-tool 兼容**：

- 第二十節 retitle 為「執行環境補充（Cowork / Codex / 同類 AI Agent 通用）」
- prompts/01 README 安裝段加咗 OpenAI Codex 條目（`~/.codex/AGENTS.md`）
- 主 README 表「適用工具」欄延長：列 Claude Cowork、Claude Code、OpenAI Codex、AGENTS.md 標準 agent、ChatGPT 等

**v0.5.0 仲未修嘅 bug**：

- prompt.md 主標題仍寫「# Claude Cowork 全域指令」— 同跨工具聲明矛盾
- prompt.md 第二十節第 15 條仍 reference 「Cowork Project」嘅 Anthropic-specific feature 名
- prompts/01 README 第七組描述仲 reference 舊章節名「Cowork 環境特殊規則(A-F)」

呢個 inconsistency 由用戶 catch 到。屬 v0.5.0 release 嘅 QC gap：QC 階段只 check 個別 markers（創作豁免、執行硬規則、第二十節 retitle）嘅命中，跳過咗全文一致性 audit（主標題 vs 章節名 cross-tool 對齊）。

### 修正

| 位置 | 修正前 | 修正後 |
|---|---|---|
| prompt.md 主標題 | `# Claude Cowork 全域指令` | `# AI Agent 全域指令（Claude Cowork / OpenAI Codex / AGENTS.md 標準通用）` |
| prompt.md 第二十節第 15 條 | `如在 Cowork Project 內則加持久化（更新 Project memory）` | `如環境支援 project / workspace 持久化（如 Cowork Project、Codex Project 等）則加持久化階段更新對應 memory` |
| prompts/01 README 第七組標題 | `### 第七組｜Cowork 環境特殊規則(A-F)` | `### 第七組｜執行環境特殊規則(Cowork / Codex / 同類 AI Agent 通用)` |
| prompts/01 README 第七組涵蓋段落 | `Cowork 專屬補充 A-F` | `第二十節 執行環境補充` |
| prompts/01 README 第七組適用對象 | `此部分專為 Claude Cowork...而設` | `此部分適用於具備用戶電腦檔案系統存取能力的 AI Agent 環境(Claude Cowork、OpenAI Codex、Amp、Cursor、Factory、Google Jules...)` |
| prompts/01 README 四階段工作流 | `Cowork Project 內加 PERSIST` | `環境支援 project / workspace 持久化時加 PERSIST，如 Cowork Project、Codex Project 等` |

## 二、你會在何時感受到變化

- 揭開 prompt.md 第一行——主標題直接寫明 cross-tool 通用，名實一致。
- AI 處理任務時提及「四階段工作流」時——唔再 hardcode Anthropic 嘅 "Cowork Project"，而係 generic 講「project / workspace 持久化」概念，再括號舉 Cowork Project / Codex Project 作例。
- prompts/01 README 第七組嘅標題、章節 reference、適用對象皆 sync 至跨工具通用版本，新讀者唔會誤以為呢套規則只適用 Claude Cowork。

## 三、保留 brand identity 嘅部分

以下位置維持 "Claude Cowork" 命名，因屬 historical brand identity / 目錄名 / GitHub URL，不改：

- prompts/01-claude-cowork-meta-instruction/ 目錄名
- prompts/01 README 主標題「# 01｜Claude Cowork Meta Instruction」
- prompts/01 README 介紹段「用於 Claude Cowork(及一般 Claude 對話介面)的治理指令」
- prompts/01 README 安裝段「### Claude Cowork」步驟（屬 Claude Cowork specific 安裝路徑）
- guide.html 嘅 title 同 metadata

Trade-off：prompt 文本本身明文跨工具通用，但 product 名稱 / 目錄識別保 historical identity，避免 ripple 連動到目錄改名、GitHub URL 改名、外部已分享 link 失效。

## 四、如何升級

### 已套用 v0.5.0 的用戶

如已將 v0.5.0 prompt 貼入 AI 工具，重新複製 v0.5.1 [`prompt.md`](https://github.com/prompt-templates/Adam-AI-Instructions/blob/main/prompts/01-claude-cowork-meta-instruction/prompt.md) 全文覆蓋舊版即可。實際治理規則內容無變動，只係 wording 嘅 cross-tool 對齊。

### 未升級 v0.5.0 的用戶

直接套用 v0.5.1（含 v0.5.0 全部功能 + 本 hotfix）。

## 五、治理層教訓（紀錄入 changelog 作 audit trail）

v0.5.0 release 嘅 QC 階段屬淺層 marker check，跳過全文一致性 audit。屬本 prompt 自身嘅「先讀後判」+「治理改動先審核」嘅 enforcement gap 活樣本。同一討論串內已有第二次 QC 漏（PowerShell line count 陷阱 + 主標題矛盾），按本 prompt 規則第十一節最後一條「同一討論串內重犯，升級為用戶明示介入」處理。
