# v0.7.2 — 一般讀者導讀升級：root README spotlight + 實驗報告焦點視覺化

**發布日期**：2026-05-23
**主旨**：v0.7.0 經實測勝出但對普通訪客而言「為何 B 勝出」嘅故事埋藏於實驗報告深處；root README 索引表亦未突出 v0.7.0 嘅勝出地位。本版本以一般讀者立場改造兩處入口頁，加入功能性 emoji 視覺定位、🏆 一句結論卡、spotlight box，讓首次訪客 30 秒內掌握「v0.7.0 — 12-節結構整合版」嘅勝出依據與安裝路徑。

---

## 一、這次更新解決什麼

### 痛點：一般讀者難以 30 秒內掌握 v0.7.0 故事

v0.7.0 釋出後嘅資訊架構問題：

1. **root README** — 索引表平等列出 prompt 01／02，未突出 v0.7.0 嘅勝出地位。第六節最近更新表中 v0.7.0 行與其他歷史版本同等視覺權重，新訪客唔知乜嘢值得即時試用。
2. **experiment README** — 為何 B 勝出嘅理由埋藏於下半頁，首屏只見「實驗背景」純文字，普通讀者掃一眼即離開。
3. **缺乏視覺定位** — 兩處入口頁全文無功能性 emoji，讀者眼球無焦點落腳。

### 修正

**root README**：

- 第四節「使用方式」與第五節「Prompt 索引」之間插入 🏆 spotlight box：一句結論（v0.7.0 — 12-節結構整合版）+ 量化指標（規則覆蓋 100%、字數 −45%、綜合分 +15.5%）+ 兩條直接行動連結（prompt 01 / prompt 02）+ 實驗報告連結。
- 第六節最近更新表 v0.7.0 行加 🏆 prefix + 粗體版本名，視覺突出勝出地位。

**experiment README**：

- 首屏加 🏆 一句結論 callout box：勝出版本名 + 量化指標 + 即時試用連結。
- 各節改用功能性 emoji 標頭：🎯 為何做這個實驗 / 🧬 實驗設計 / 📋 8 場景實測案例集 / 📊 四輪實測維度 / 🏆 實驗結果 / ✅ 規則覆蓋率 / 📈 排名 / 💡 為何 B 勝出 / 🎁 實用價值 / 📁 檔案索引 / 📚 官方文件來源。
- 三檔策略對比表加 ⭐ 標記 B 中度行。
- 排名表加 🏆 🥈 🥉 標記前三名。
- 檔案索引 v_b_moderate.md 行加 🏆 標 + 「**已採用**」粗體。

## 二、設計原則（與用戶偏好對齊）

按用戶偏好「功能性 emoji 只作視覺定位，每枚單一語意，只放標題或項目開首，不插入正文句中，不作裝飾」：

- 🏆 — 勝出標記
- ⭐ — 焦點強調
- 🥈 🥉 — 排名輔助
- 🔎 — 重點問題
- ✅ — 通過項
- 📊 📈 📉 — 數據指標
- 🎯 — 目標
- 🧬 🧪 📋 — 實驗工具
- 💡 — 為何成立
- 🎁 — 用戶價值
- 📁 — 檔案索引
- 📚 — 文件來源
- 🚀 — 行動連結
- 👉 — 即時動作指引

每枚單一語意，只放標題或項目開首，不裝飾、不堆砌。

## 三、你會在何時感受到變化

- 首次訪客開 root README，第四節與第五節之間即見 🏆 spotlight box，30 秒內掌握「v0.7.0 — 12-節結構整合版」嘅勝出地位、量化指標、安裝路徑。
- 第六節最近更新表中 v0.7.0 行視覺突出，與其他歷史版本區分。
- 訪 experiment 報告首屏即見「🏆 一句結論」，知道 B 勝出、勝出依據、即時試用連結，毋須讀畢全文。
- 報告各節按功能性 emoji 視覺分組，眼球有焦點落腳。

## 四、如何升級

無 prompt.md 內容變動，套用 v0.7.0 / v0.7.1 嘅用戶毋須重新貼入。直接 pull repo 最新版本或開 GitHub 線上查 README 即可。

## 五、治理層教訓

- 「實驗勝出版本」釋出後，未即時思考「一般讀者打開 root README / 報告頁，30 秒內能否掌握重點」屬讀者立場缺失。技術人員寫嘅 README 容易預設讀者已掌握 context；本版本提醒：每次重要 release 後須做「30 秒首屏測試」 — 想像首次訪客掃一眼，是否能即時掌握「乜嘢勝出、為何勝出、即時試用連結」三項。
- 功能性 emoji 對非技術讀者導讀效益顯著，但前提是「每枚單一語意、只放標題或項目開首、不裝飾」。亂用 emoji 會反效果。
- 已記入 memory（user feedback layer）等下次同類發佈用。
