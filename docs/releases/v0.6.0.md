# v0.6.0 — 新增 Claude Code 版全域指令（含機密處理及 Windows 桌面附加）

**發布日期**：2026-05-17
**主旨**：在 01（Claude Cowork Meta Instruction）通用骨幹之上新增第二份 prompt，定位為 Claude Code 全域指令版本，補入兩條 Claude Code 場景常用的附加規則：機密處理（跨作業系統通用）與 Windows 桌面破壞性命令零容忍。

---

## 一、這次更新解決什麼

### 痛點一：機密值在 Claude Code 場景下的洩漏路徑

Claude Code 常處理含 `.env` / credentials / API key 的項目，AI 預設可能在以下位置複述機密值，造成不可逆的外洩：

- 對話回覆正文（「我看到你的 `OPENAI_API_KEY` 是 `sk-xxx…`」）
- 建議的 git commit message（commit 後 history 永久留痕）
- 建議寫入 issue / PR 描述（可能 public repo）
- debug log 檔（log 上傳分析時帶出）
- 新建檔案（如 sample config 不慎含實值）
- 呼叫外部 API 時誤帶入 query string

01 通用治理規則未直接覆蓋此場景。

### 痛點二：Windows 桌面破壞性命令的特異變體

Windows 環境下 `cmd /c rmdir` 家族指令容易因以下情景造成 catastrophic deletion：

- 路徑含空格但引號處理錯誤，`"C:\Project Files"` 解析為 `C:\` 磁碟根
- 環境變數展開出意外結果（`%USERPROFILE%` 為空時解析為 root）
- caret `^` 跳脫處理不一致，導致實際命令與意圖不符

01 第二十節通用條已禁 `rm -rf` + 禁外部殼層 `cmd /c` 執行檔案系統修改，但 Windows 平台特異變體值得獨立硬封殺，避免 AI 在用戶要求清空空資料夾時用 `cmd /c rmdir /s /q` 執行而誤觸路徑解析陷阱。

## 二、新增內容

### 第二份 prompt：`prompts/02-claude-code-meta-instruction/`

三件套齊備：

- **`prompt.md`** — Prompt 原文，可直接複製貼至 `~/.claude/CLAUDE.md` 全域或項目根目錄 `CLAUDE.md`
- **`README.md`** — 文字介紹頁，說明痛點、規則、01 vs 02 如何選用
- **`guide.html`** — 互動式 HTML 指南，含 SVG 視覺化說明 02 vs 01 差異

### 結構

- **第一至二十節**：與 01 [`prompt.md`](https://github.com/prompt-templates/Adam-AI-Instructions/blob/main/prompts/01-claude-cowork-meta-instruction/prompt.md) 為單一真源，逐字對齊。01 後續升版時 02 同步更新，避免跨檔漂移。
- **第二十一節 機密處理**（OS-agnostic 全平台通用）
  - 讀取含機密檔案時，回覆中以 `<REDACTED>` 或「見檔案第 N 行」代替複述。
  - 絕不將機密值寫入：git commit、issue、PR 描述、log 檔、新建檔案、或外部請求。
  - 涉及機密的變更必須明確標示「此處含機密，請人工檢閱」。
- **第二十二節 執行環境特定附加（Windows 桌面）**（僅 Windows 桌面生效）
  - `cmd /c rmdir` 家族零容忍：`cmd /c rmdir`、`cmd /c rd`、`cmd /c rmdir /s /q` 及任何混淆變體（caret `^`、雙引號、環境變數展開等）全面封殺。
  - Windows 路徑安全：引號驗證、磁碟根目錄禁區（`C:\`、`D:\` 等）、路徑歧義時不執行。

## 三、你會在何時感受到變化

套用 02 後：

- AI 讀 `.env` 後不再在回覆中複述具體 API key 值，改以 `<REDACTED>` + 「見 .env 第 N 行」表達。
- AI 不再建議將機密值寫入 git commit message、issue / PR 描述、log 檔、新建檔案。
- Windows 桌面下 AI 不再用 `cmd /c rmdir /s /q` 系列指令清理目錄，改用 native PowerShell / 工具原生 API；遇路徑解析歧義時主動停手不執行。
- macOS / Linux 用戶套 02 亦可使用，第二十二節 Windows 附加會自動跳過，其餘 21 節跨平台適用。

## 四、01 vs 02 怎麼選

| 場景 | 建議 | 理由 |
|---|---|---|
| Claude Cowork 為主、純對話介面 | 01 | 通用治理規則已足夠 |
| Claude Code 為主、會接觸機密檔案 | 02 | 需要第二十一節機密處理 |
| Claude Code 為主、Windows 桌面用 | 02 | 需要第二十二節破壞性命令零容忍 |
| Claude Code 為主、macOS / Linux 用 | 02 | 第二十二節自動跳過，其餘 21 節跨平台 |
| OpenAI Codex / AGENTS.md agent | 01 或 02 皆可 | 視乎是否需要機密處理 + Windows 附加 |
| 純對話介面 ChatGPT 等 | 01 | 無檔案系統存取，02 多出嘅節不適用 |

## 五、如何升級

### 已套用 01 的用戶

- 如只用通用治理規則，繼續用 01 即可，本版本不影響你。
- 如想補入機密處理，可單獨抽取 02 第二十一節貼至 01 之後；或整套換成 02。
- 換 02 時：複製 [`prompts/02-claude-code-meta-instruction/prompt.md`](https://github.com/prompt-templates/Adam-AI-Instructions/blob/main/prompts/02-claude-code-meta-instruction/prompt.md) 全文覆蓋原 01 內容即可，第一至二十節逐字同源無需重新理解。

### 新用戶

直接套用對應版本（純對話用 01；Claude Code 用 02）。

第一至二十節以 01 [`prompt.md`](https://github.com/prompt-templates/Adam-AI-Instructions/blob/main/prompts/01-claude-cowork-meta-instruction/prompt.md) 為單一真源，02 維護時逐字對齊；如 01 後續升版（加新規則、改條款編號等），02 第一至二十節同步更新。第二十一、二十二節為 02 獨有，獨立維護。
