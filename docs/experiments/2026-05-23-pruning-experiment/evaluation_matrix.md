# 評分矩陣

這是 2026-05-23 瘦身實驗的歷史評分表。

當前指令已在後續版本更新；本檔只保留當時的測試方法與結果。

---

## 一、評分方法

實驗使用 8 個場景，檢查每個版本是否保留應觸發的規則。

每條規則按三種狀態評分：

| 狀態 | 分值 |
|---|---:|
| 覆蓋且表述清楚 | 1.0 |
| 覆蓋但表述較弱 | 0.5 |
| 未覆蓋 | 0 |

核心規則不得遺失。

---

## 二、場景總覽

| 場景 | 檢查重點 |
|---|---|
| 單檔小修改 | 是否使用清楚的修改交付方式，且不誤觸多檔計劃。 |
| 多檔治理改動 | 是否先列完整計劃，並先做只讀審核。 |
| 歧義指令 | 是否先列合理假設，避免把所有判斷丟回給使用者。 |
| 可驗證事實提問 | 是否先核實，再回答。 |
| 創作類任務 | 是否避免把創作任務硬套成工程流程。 |
| 計算 | 是否展示步驟並驗算。 |
| JSON 輸出 | 是否保留鍵名與缺值處理。 |
| 使用者指出錯誤後重做 | 是否停下來重新核對，而不是換個說法繼續猜。 |

---

## 三、結果摘要

| 版本 | 規則覆蓋 | 閱讀效率 | 與使用者優先序對齊 | 整體判斷 |
|---|---|---|---|---|
| 原版本 | 完整 | 偏重 | 可用 | 內容太散。 |
| A 保守 | 完整 | 略好 | 略好 | 改善不足。 |
| B 中度 | 完整 | 明顯改善 | 最平衡 | 採用。 |
| C 激進 | 完整 | 最短 | 有壓縮風險 | 不採用。 |

---

## 四、後續解讀

這份矩陣不是要證明某個版本永遠最好，而是留下當時的驗證方法。

若未來再重構指令，應沿用同一精神：先列場景，再逐條檢查規則是否仍能觸發。
