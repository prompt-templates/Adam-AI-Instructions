# v0.5.0 — 創作豁免、執行硬規則、Codex 兼容、緊湊化

**發布日期**：2026-05-15
**主旨**：四件事一齊處理——(1) 加「創作類任務例外」豁免，創作場景唔再硬塞工具化骨架；(2) 加條款編號 + 回覆骨架執行硬規則，唔再口惠而實不至；(3) 修正下一步選擇題嘅 markdown render bug（A/B/C 黐埋）；(4) 明文兼容 OpenAI Codex / AGENTS.md 標準 AI agent；同時整份 prompt.md 緊湊化 296 → 248 行。

---

## 一、這次更新解決什麼

### 痛點一：v0.4.0 對創作任務不友善

**之前是這樣**：

叫 AI 幫畫海報、寫詩、寫故事、廣告文案，AI 仍照樣硬塞「全圖優先五區段表格」「四階段工作流（規劃→閱讀→修改→品質檢查）」「回覆骨架🔎重點 + 交付清單」「計算四步法」呢類工具化骨架。原 v0.4.0 規則只對「事實核對」嗰節做咗創作豁免（「除非屬創作、虛構、幻想、純推理」），其他規則照樣 active，把抒情輸出弄成 to-do list。

**現在會變成這樣**：

個人偏好段加「創作類任務例外」明文豁免：設計、故事、詩、廣告文案、純想像、虛構等不以事實可驗收為目標嘅任務，自動豁免**全圖優先五區段、回覆骨架硬骨幹、四階段工作流、計算四步法、可量指標／驗收條件**；語言分層、合作模式、用語紀律、回覆語體仍適用（保溝通質量基本）。

### 痛點二：條款編號 + 回覆骨架執行未到位

**之前是這樣**：

v0.4.0 已寫「不做句子主體」「預設三行🔎重點 + 交付清單」嘅 principle，但 AI 經常違規：選擇題寫「依 §3.5 + §12 處理」（編號做主體用戶讀唔懂）；長篇結構性報告省略🔎重點段直入正文（骨架預設失效）。屬規則寫咗但執行未夠硬。

**現在會變成這樣**：

第十七節用語紀律加「執行硬規則」(a)(b) 兩條：

- (a) 條款編號（§X、X.Y 等）必須前置中文白話描述對應事實，編號只可放括號或行尾次要標註；句子主體位置出現編號（無中文白話前置）即違規。
- (b) 任何回覆（含長篇結構性報告、純對話、選擇題回應）必須啟動第五節回覆骨架：開首三行內「🔎」重點 + 交付清單（如適用），缺一即違規。

兩條每次違反**即當下 self-flag 改寫**，不視為「下次注意」。

### 痛點三：選擇題 A/B/C 黐埋同一段

**之前是這樣**：

v0.4.0 第六節嘅選擇題格式定義將 `🚀 *下一步揀一條*` + `A.` + `B.` + `C.` + `推薦：X` 寫喺連續 `>` 行（無 blank line 分隔）。Markdown CommonMark 規範會將連續 quote line 合成單一 paragraph，render 結果係 A/B/C 黐埋一段，用戶要逐字搵 A 在哪、B 在哪。

**現在會變成這樣**：

第六節格式定義加 `>` blank line 分隔，並明文寫「每個選項之間必須 `>` blank line 分隔，否則 markdown render 結果 A/B/C 黐埋同一 paragraph」。新版選擇題每選項各佔一段，視覺清晰。

### 痛點四：本指令未明文兼容 Codex / AGENTS.md 標準

**之前是這樣**：

本指令原意設計給 Claude Cowork，但搜索證實 OpenAI Codex / Amp / Cursor / Factory / Google Jules 同樣採用 `AGENTS.md` 作 custom instruction 入口（cross-tool open standard）。本 prompt 95%+ 規則可直接通用，但 v0.4.0 章節名 hardcode "Cowork"，未明文表態 cross-tool 兼容。

**現在會變成這樣**：

- 第二十節 retitle 為「執行環境補充（Cowork / Codex / 同類 AI Agent 通用）」。
- prompts/01 README 安裝段補 OpenAI Codex 條目：放 `~/.codex/AGENTS.md` 全域 或 項目根 `AGENTS.md`。
- 主 README 第五節 Prompt 索引表「適用工具」欄延長：列 Claude Cowork、Claude Code、OpenAI Codex、AGENTS.md 標準 agent（Amp / Cursor / Factory / Google Jules）、一般 Claude / ChatGPT 對話介面。

## 二、結構整理（緊湊化）

整份 prompt.md 由 **v0.4.0 296 行壓至 v0.5.0 248 行（-48 / -16.2%）**，保所有規則內容、保 markdown 慣例。主要 saving：

- 第十一節先讀後判：9 bullets 合「四類捷徑」單條（含 4 個 sub-letter 子點）
- 第十二節治理改動先審核：6 點自檢由獨立 bullets 改 inline 列舉
- 第十三節補丁式：8 bullets 壓至 5 bullets，補丁格式硬規則 3 子點 inline
- 第二十節執行環境補充：22 條壓至 19 條（同類條合句，如層次分類 8+9 合一、外部平台 API 14+15 合一）
- 第三節全圖優先「不觸發」「觸發時禁止」list 緊湊化為單段
- 第十七節反正例由 4 例壓至 2 例（核心 + 本 session 違規 self-incriminate 例）

## 三、你會在何時感受到變化

- 叫 AI 處理創作任務時——AI 唔再硬塞五區段表格、四階段工作流、計算四步法。
- 揀 AI 選擇題時——A/B/C 每個選項分行清晰，唔再黐埋。
- AI 寫條款編號時（§3、§12 等）——必先有中文白話描述對應規則，編號只放括號附註。
- AI 任何回覆都啟動「🔎重點 + 交付清單」骨架——唔再長篇 report 跳過骨架直入正文。
- 用 OpenAI Codex（或 Amp / Cursor / Factory / Jules）嘅用戶可直接放 `~/.codex/AGENTS.md`，無需 adapt。
- 整份 prompt.md token saving 16.2%，AI 載入時認知負載降低。
