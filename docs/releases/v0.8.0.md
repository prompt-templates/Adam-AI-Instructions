## 二、新增第十五節結構

### Plan mode 使用時機

- 強制 plan mode：修改三個或以上檔案；不熟悉嘅代碼區；改動方法不確定；涉及外部系統呼叫
- 跳過 plan mode：單檔小改（typo、加 log line、rename variable、改 commit message）— 直接做更快
- 判斷準則：「如果用一句話可描述 diff，跳過 plan」

### 主動提驗收標準（最高槓桿原則）

- 對任何修改類任務，動工前必先確立驗收手段；無驗收手段不修改
- 修改後必運行驗收，不以「應該沒事」交付
- 原則：「If you can't verify it, don't ship it」（與既有第四節「驗收測試」呼應，但 Claude Code 場景強調 Claude 主動提）

### Context 管理觸發點

- 同一錯誤被修正 2 次後仍未解決 → 主動建議用戶 `/clear` 重啟乾淨 context
- 切換到無關任務 → 主動建議 `/clear`
- 研究型任務（codebase exploration、跨檔搜尋、需讀 10+ 檔）→ 優先用 subagent 隔離 context

### CLI tools 優先 over 直接 API call

- 涉及 GitHub／AWS／GCloud／Sentry 等外部平台，優先用對應 CLI tool（`gh`、`aws`、`gcloud`、`sentry-cli`）
- 不熟悉嘅 CLI tool 用 `<tool> --help` 先學再用

### 失敗模式警示（主動識別並避免）

- **Kitchen sink session**：同一 session 切換多個無關任務 → 中間 `/clear`
- **Over-correction**：2 次修正失敗 → `/clear` 並重寫 prompt
- **Trust-then-verify gap**：產出未驗證 → 必跑驗收
- **Infinite exploration**：研究範圍未定 → 用 subagent 限制 scope
- **Over-specified CLAUDE.md**：本 prompt 自身亦適用「狠手剪裁」原則（自我引用 v0.7.0 瘦身實驗作為已驗證範例）

## 三、你會在何時感受到變化

- Claude Code 環境下 Claude 主動提驗收標準，毋須用戶每次提醒
- 同一錯誤被修正 2 次仍未解決時，Claude 主動建議 `/clear` 重啟 — 而不是繼續第三次修補污染 context
- 研究型任務（讀 10+ 檔）Claude 主動用 subagent 隔離，主 session context 保持乾淨
- 涉及 GitHub／AWS 等外部平台時 Claude 預設用 CLI tool（`gh`、`aws`）— context 更省、認證更可靠
- 5 項失敗模式 Claude 主動識別並避免，毋須用戶事後糾正
- Cowork / Codex 環境用戶 — 第十五節自動跳過，無影響
