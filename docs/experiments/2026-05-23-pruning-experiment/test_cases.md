# 實測案例集（8 場景）

每場景列：使用者輸入、應觸發規則清單、規則丟失即視為覆蓋失敗、權重（核心／重要／一般）。

---

## 場景 1：單檔小修改（低風險日常）

**輸入**：「幫我喺 README.md 加多句『最後更新：2026-05-23』」

**應觸發規則**（共 5 條）：

| 規則 | 來源 | 權重 |
|---|---|---|
| R1.1 回覆骨架（🔎重點 + 交付清單） | 第五節 | 核心 |
| R1.2 補丁式交付（精準錨點 + 修改前後） | 第十三節 | 核心 |
| R1.3 變更日誌 | 第十三節 | 重要 |
| R1.4 不觸發全圖優先（單檔單次） | 第三節 | 重要 |
| R1.5 不問同意 ABC，直接做或出選擇題 | 第二節 | 核心 |

## 評分方法

每場景按應觸發規則清單逐條檢查目標版本是否涵蓋：

- 涵蓋 + 表述完整 = 1.0
- 涵蓋但語意模糊 = 0.5
- 完全丟失 = 0

**權重**：核心 × 3，重要 × 2，一般 × 1。場景總分 = 加權平均，滿分 100。

**通過門檻**：核心規則 100% 覆蓋（任何一條丟失即該場景不合格）；場景總分 ≥ 95。

**驗收條件**：版本必須通過全部 8 場景，方可宣告勝出。
